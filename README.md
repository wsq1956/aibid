# AIBID 工作台 · 界面演示

金宝马 AI 投标与方案助手（AIBID）的界面演示。
打开 <https://wsq1956.github.io/aibid/> 即可浏览，无需安装任何东西。

## 这个演示是什么

界面是**真的**，数据是**跑出来的**，只有后端是没有的。

- **界面是真的** —— 页面里的前端逻辑与本地运行版**逐字相同**。本演示没有为
  展示另写一套界面；那样演示的就不是真东西了。（`index.html` 是自包含单文件，
  其中的 `app.js`、`style.css` 与运行版逐字一致，可用内联前后的文件比对验证。）
- **数据是跑出来的** —— 页面上每一个数字，引用偏移、哈希链、自检覆盖率，
  都由本地服务端真实执行后导出固化，不是手写编造的。
- **后端是没有的** —— 静态页不含服务端逻辑。因此生成结果是**回放**而非实时
  计算，审定按钮会明确拒绝。

**全部为合成演示数据，不是公司真实资质业绩。**

## 演示版与完整版的差别

| 能力 | 本演示 | 本地完整版 |
|---|---|---|
| 浏览界面 | ✅ | ✅ |
| 研判清单、资质业绩库、审计链 | ✅ 导出的快照 | ✅ 实时读取 |
| 生成标书初稿 | 回放导出结果 | 实时生成并回查 |
| 输入未预置的关键词 | 返回「阻断」 | 实时检索，查不到即阻断 |
| 审定补签四元组 | ❌ 明确拒绝 | ✅ 实时写入审计链 |

最后一条是刻意的：**这个系统的全部价值就在于审计链不可篡改，演示版更不能
自己破例。** 所以本页宁可报错，也不在前端伪造一条审计记录。

未预置的关键词同样返回「阻断」，这与真实系统的 fail-closed 行为一致 ——
查不到事实就不出稿。区别只在于：真实系统真的去检索了，本页没有后端可查。

## 为什么是单文件

`index.html` 把样式、数据与脚本全部内联，整页只有 **1 个请求**。
原因是实测：本机到 `github.io` 的链路上单个资源约有 8% 概率握手超时；
分体版一页要取 5 个资源，三次打开就有一次是坏的。合并后失败面降到最低。

单文件由 `scripts/build_static_page.py` 生成（在完整工程里）：
读 `index.html`，把 `<link>` 与 `<script src>` 就地换成内联内容，
**不重写任何一行 JS/CSS**。数据由 `scripts/export_static_demo.py`
调用真实流水线导出。两个脚本都可复现本页全部内容。

## 完整版

完整工程为 Python 标准库实现，无第三方依赖，需 Python 3.11+：

```
启动AIBID.bat       Windows 双击
启动AIBID.command   macOS 双击
启动AIBID.sh        Linux
```

浏览器自动打开 `http://127.0.0.1:8765/`。
