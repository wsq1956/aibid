# AIBID 投标小助手

**上传招标文件 → 上传公司资料 → 导出投标文件。**
打开 <https://wsq1956.github.io/aibid/> 即可使用，不需要安装任何东西。

全部计算在你的浏览器里完成，**没有后端**，资料不出你的设备。

- 本页（`index.html`）= 投标小助手
- `demo.html` = 早先的 AIBID 工作台界面演示（静态快照，非工具）

## 能做什么

| 步骤 | 做什么 |
|---|---|
| ① 招标文件 | 拖入 `.txt` / `.md` / `.docx` / `.pdf`，读出项目名称、招标编号、招标人、投标截止时间、保证金、工期，以及全部含「必须／应当／不得」的硬性要求 |
| ② 公司资料 | 拖入资质证书、专利证书、业绩清单（可多选，也可直接粘贴），自动抽出**事实条目**，每条保留原文与出处行号 |
| ③ 生成导出 | 程序逐字拼接成初稿，导出 Word（留痕版／净版）、Markdown、纯文本，或打印存 PDF |

## PDF

PDF 是这一版的重点。手写的解析器读不了中文 PDF，所以把 **pdf.js** 和
**169 个中文 CMap 表**一起打包进了单文件里（约 3MB，仍然零依赖、可离线）。

| 情况 | 结果 |
|---|---|
| 文字版 PDF（Word／WPS 导出） | 完整读出 |
| 只声明预定义 CMap、不嵌 ToUnicode 的 PDF | 完整读出（靠打包的 CMap 表；没有它就是**一个字都取不到**） |
| 加密 PDF | 空用户口令直接开；要口令会问 |
| 超大文件 | 按需读取。实测 **236MB / 39 页 1.2 秒** |
| **扫描件（整页是图）** | **读不出来，改用「对照录入」** |

### 扫描件为什么不 OCR

实测过，不行。拿真实宣传册（39 页扫描件）跑 tesseract 中文模型：

| 原文 | 识别结果 |
|---|---|
| 专利申请受理通知书 | 专利让请受理通知**首** |
| 2023年8月17日 | 2023**秆**8**H**17**HH** |
| 2023年武汉市生态环境保护先进适用技术指导目录 | 2023**咎杜议**市生态**杂境负沪先许活出枝术朱叶日录** |

大字勉强认对，**证书编号和日期这些真正要紧的小字错得离谱**。标书是要负法律责任的 ——
塞一个认错的编号进去，比读不出来更糟。

所以扫描件改为**对照录入**：左边摆原图（可放大到 6 倍、约等于原始像素），
右边照着敲。**敲进去的字就是原文**，一样进事实库、一样记留痕。

## 三条纪律

**一、写进标书的每个字都有出处。**
正文里那句话，是把名称、签发单位、日期、编号四个字段**照抄原文**后由程序拼起来的。
每处引用都能点开，看到它出自哪个文件的哪一行。这条承诺**可自动检验** ——
程序逐条检查每个字段是否真能在原文里原样找到；对不上就退回插入整行原文，
并明确标出。**没有任何模型参与改写。**

**二、缺材料就拒绝出稿。**
资质、证书、专利、业绩四类，哪一类不够就整体拒绝生成并列出缺什么。不拿占位文字凑数。

**三、每一次动作都进哈希链。**
上传、抽取、改、删、生成、导出、扫描件录入全部留痕，改动任意一条其后全部失配。

## 支持情况

| 格式 | 支持程度 |
|---|---|
| `.txt` / `.md` | 完整支持，自动识别 UTF-8 与 GBK |
| `.docx` | 完整支持（自己读 ZIP + 解压 + 解析 XML，零依赖） |
| `.pdf` | 完整支持，见上 |
| `.doc` | 不支持，请用 Word 另存为 .docx |

## 已知限制

- 扫描件需要**人工录入**，页数多时要敲一阵子 —— 这是刻意的取舍，理由见上。
- 事实抽取靠规则，材料写法千变万化，覆盖不到的地方会漏抽；漏了可手工补。
- **不保证材料本身符合本次招标要求。** 工具只保证「引用的文字与材料原文逐字一致」，
  不保证这些资质业绩满足招标文件的资质等级、业绩数量要求 —— 那要人来判断。
  净版导出提交前请自己复核。
- **没在鸿蒙浏览器上实测过**（开发机是 openEuler + Chromium）。

## 数据

全部存在你浏览器的 localStorage 里，不上传任何服务器。
换浏览器或清理浏览器数据会丢失，**重要内容请及时导出**。

## 技术

单文件、零依赖、离线可用。内含 pdf.js（原样内联，未改一行）、169 个中文 CMap 表、
自实现的 ZIP 读取（配 `DecompressionStream`）、自实现的 SHA-256（不用 `crypto.subtle`，
因为它在 `file://` 下拿不到）、GBK 解码回退。

**全部为合成演示数据，不是公司真实资质业绩。**
